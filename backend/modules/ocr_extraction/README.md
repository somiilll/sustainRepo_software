# Extraction handoff pack (for Emergent)

A drop-in replacement for the extraction backend behind SustainRepo's **OCR Extraction** page. Read `EMERGENT_BUILD_NOTES.md`, then `SPEC.md`.

```
SPEC.md                 what it does, decisions, UI changes, acceptance criteria
contracts/              extracted_row + save_all JSON schemas, openapi.json, real examples
mappings/               taxonomy (generated by _build_taxonomy.py), formula fields, policy, units, HSN/SAC rules, pricing (credits)
prompts/                the exact extraction / layout prompts, JSON schemas and classifier questions
engine/extractor_core/  reference Python package (pure functions; network only in llm.py and decider/providers.py)
engine/tests/           pytest, 116 tests, no network
golden/                 manifest, expected rows, evaluate.py, REPORT.md
testbench/              local review app on port 8040 (FastAPI + plain JS)
EMERGENT_BUILD_NOTES.md  START HERE: what is built, rules to keep, what to supply, known gaps
EMERGENT_FOLLOWUP.md    what we still need from Emergent
```

## Wiring it into SustainRepo (step by step)

1. **Copy the package.** Put `engine/extractor_core` and `mappings/` in the backend. `config.py` finds `mappings/`
   next to `engine/`; set `EXTRACTOR_MAPPINGS_DIR` if you put it elsewhere.
2. **Dependencies.** `engine/requirements.txt`: `anthropic`, `requests`, `openpyxl`, `pandas`, `pymupdf` and `pillow`, plus
   `xlrd` for legacy .xls files and `pillow-heif` for HEIC phone photos.
3. **Keys** (environment variables):
   - `ANTHROPIC_API_KEY`: reading documents, Excel layouts, last-resort classifier.
   - `OPENROUTER_API_KEY`: Jev.
   - `OPENAI_API_KEY`: OpenAI Decisions.

   Any of the three classifier keys can be missing; the chain skips that provider.
4. **Memory.** `Memory(path)` is SQLite. For Mongo, implement the same methods (listed in `EMERGENT_BUILD_NOTES.md` section 4). Use one store per organisation (the `org`
   argument). This is what makes corrections stick.
5. **Run a job in the background.** Uploads must not block the request.
   ```python
   eng = Engine(memory, org=org_id, org_context={"name": org.name, "industry": org.industry},
                facilities=[{"id", "name", "aliases", "consumer_numbers", "gstins", "address_keywords"} ...])
   result = eng.run(paths, mode="fast" | "think", progress=lambda p: job.update(p))
   ```
   `result["rows"]` feeds the review table (`contracts/extracted_row.schema.json`).
   `result["documents"]` feeds the Documents panel.
   Store `result["items"]` and `result["decisions"]` with the job, because edits need them.
6. **Edit a row** (what `PATCH /api/jobs/{id}/items/{item_id}` does in `testbench/app.py`):
   - change the stored item's quantity, unit, amount, period or facility;
   - build a decision `{activity_id, confidence: 0.99, source: "user", context}`;
   - call `eng.rows_for_item(item, decision)`, then replace every row with that `item_id`;
   - if "remember" is ticked, call `eng.classifier.remember(item, decision, source="user", scope="vendor")`
     (`scope="all"` only when the user ticks "any vendor").
7. **Approve / reject.** Store `review.state` per row, and apply it to the parent and its companions together.
   Block approval when `calc.formula_id`, `facility.id` or `reporting_period` is empty.
8. **Save-all.** `export.save_all_payload(rows, org)` produces `contracts/save_all.schema.json`. For each record:
   - write the emission record for `subcategory_id` with `fields`; the keys are the formula's own keys plus `<key>_unit`;
   - split per `period_allocation` when a bill covers two months;
   - attach `evidence`;
   - link companion records by `parent_row_id`.
9. **Facilities.** Pass the org's facilities, including consumer/meter numbers and GSTINs; the matcher uses them in that order.
10. **Settings.** Expose `mappings/policy.json` (thresholds, waste-transport mode, companions on or off) as per-org settings with these defaults.

**Credits.** After each job, `Ledger(...).record(org, job_id, result["usage"]["events"])`. Show
`balance(org)` in the sidebar and `report(org, since)` on a Credits page (the testbench `#usage` page is the reference).
Prices live in `mappings/pricing.json`; see SPEC section 7.

## What Emergent still has to fill in

`category_id`, `subcategory_id` and `emergent_formula_id` are `null` until we receive Emergent's JSON export
(`EMERGENT_FOLLOWUP.md`). Until then Save-all can map by `subcategory_label` + `formula_id`; both match the names
in Emergent's formula report.

## Running locally

```bash
py -3.11 -m pytest extraction-handoff/engine/tests -q
py -3.11 -m uvicorn --app-dir extraction-handoff/testbench app:app --port 8040
py -3.11 extraction-handoff/golden/evaluate.py
py -3.11 extraction-handoff/prompts/_export.py
```

The testbench reads keys from the file named by `EXTRACTOR_ENV_FILE`. Otherwise it looks for `testbench/.env`;
copy `.env.example` to create one.
